## 尚待批准和验证的部署事项

1. **厂商撤销与应用控制**：先取得并实测厂商适用机制，完成旧Ticket不能重连/抢占、旧标签页不能输入、普通用户不能执行任意shell或进入账号设置的验证。已准备[咨询正文](VENDOR_REQUEST.md)。断连API成功、2507错误或前端隐藏都不算通过。
2. **受保护控制通道**：现有Linux→手机私网5555的单目标TCP检查超时。传统公网ADB不能当作长期加密通道。候选方案为复用Linux现有SSH入口，由手机通过严格主机公钥校验建立仅限本任务回环端口的反向SSH连接，再承载原ADB鉴权与Frida TLS。需要先审批专用受限SSH用户/公钥和精确转发限制；本轮没有实施，也没有把公网地址伪装成私网。若此方案不可用，仍暂停，不新增网络资源。
3. **常驻云身份**：现有Linux没有挂载RAM角色。需要仅含必要云手机动作的任务专用身份；由官方确认API资源级限制后再提交精确策略和凭据保存方案供Owner批准。不会复制Owner电脑的OAuth或申请FullAccess。
4. **厂商安全策略**：现策略允许Clipboard readwrite、Html5FileTransfer all、Camera on、LocalDrive readwrite。拟为本单实例组创建并绑定独立限制策略，不改共享策略；具体变更及回滚须Owner批准。未修改当前策略。
5. **HTTPS入口**：现Linux nginx有2份配置包含HTTPS证书引用，尚未确认可复用的独立来源/证书。候选nginx片段不是可直接应用配置，不得覆盖现有server。共享origin上其他应用具有同源访问能力，需优先选择独立受控origin并先确认入口和路由改动；不自行买域名或开放公网。

以上依次收敛，不能用一个宽泛“同意部署”代替具体权限或公开入口确认。任何新增费用、网络/IAM、安全组/防火墙或共享服务变化均按规格先确认。

## 在门槛通过后执行的安装流程

以下是维护者流程，**不是已执行结果**。日常策划不需要这些命令。

1. 在现有Linux创建本任务独立服务用户及 `/srv/huuuge-self-service`。源码、隔离venv、厂商SDK、data分开；data目录0700，SQLite/凭据0600。保留TASK-0031原路径和结果。
2. 将已提交Git归档部署到release目录，记录实际commit。独立Python3.11环境安装本目录requirements及`deploy/cloud/requirements.txt`；不替换系统Python、原venv或全局ADB。官方SDK从[厂商下载页](https://help.aliyun.com/zh/ecp/get-cloud-phone-sdk-and-demo)取得，按企业使用许可保存在受控vendor目录。
3. 由经批准的最小云身份、SSH/管理通道完成运行适配；匹配已安装Huuuge版本、ARM64和descriptor。每片段生成短期TLS证书/令牌，保持证书校验和Frida鉴权；仅本任务回环端口。此步骤代码尚未完成，不能提前启用服务采集。
4. 从`workbench.example.json`生成私有配置。填实际HTTPS origin、现有单实例及真实部署/descriptor版本，仍保持admission=false。配置不接受第二游戏。
5. 维护者在受控终端执行 `python -m self_service.admin user <工作台别名>`；交互设置密码，日志和命令行没有密码。`revoke <别名>`禁用账号并撤销记住登录。没有注册页面或默认密码。
6. 经Owner批准后安装独立systemd单元、精确HTTPS路由；只对任务服务启停/更新，不重启主机、晨会、共享nginx以外其他服务。nginx变更需先 `nginx -t`，然后仅reload；回滚精确移除本任务片段并恢复备份。
7. 云端执行组件测试和真实门槛验证后才开放admission；完成[验收表](ACCEPTANCE.md)全部A—F，最后交Review。

## 默认行为与日常维护

- 面板2秒轮询，10秒无可信更新撤销绿色；准备/停止为灰，采集中绿，错误红，正常结束红并显示停止图标和已保存。
- READY需要本段hooks、真实新增捕获/成功解码及手机心跳。只连接SDK或有PID不变绿。暂无RPC但心跳健康可继续等待数据。
- 默认3分钟浏览器重连宽限；原页面10秒不再续租后，可由同一操作者恢复画面，仍须先撤销原厂家凭证。重复开始/结束幂等。
- 研究会话包含不可覆盖片段，最多3次片段启动；错误恢复记缺口，不调用原controller的retry-start来续写已有片段。
- 结束先撤销desired-state，停止/flush/回读，然后封存与构建ZIP。控制凭证撤销不明时继续占用手机，但已停止的结果可下载。正常结束与不完整结果不混为一类。
- ZIP原子发布后重复下载不重采。大整数输出十进制字符串；未知字段默认不导出；保留必要下注、响应、免费转、奖励变化和活动进度，说明缺失及语义未确认项。
- 当前只有启动前至少5GiB可用空间检查；运行中容量阈值、每轮TLS轮换和进程清理仍待完成，不得宣称无人值守已通过。
- 暂不自动删除数据。新数据保留周期、单次/总容量与删除机制待Owner确认；旧312证据永久排除在任务清理逻辑外。

## 停止、升级与回退

日常用户使用“结束并下载”。维护者先关闭新会话准入，确认当前研究正常收尾、厂家凭证失效、任务进程和转发清理，再停止两个独立单元。升级到另一个已记录release时保持原SQLite和数据；当前没有数据迁移，不覆盖既有片段。

若收尾不能确认，保留租约和数据，网页显示红色，不允许下一人接管。systemd异常退出也不等于finalized；重启后按原片段证据恢复。只回退本任务代码与已备份任务配置，不回退晨会或其他服务，不重启/清数据/重做Google环境。

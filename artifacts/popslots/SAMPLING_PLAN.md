# Pop! Slots 数值采样方案（RTP 精度与预算）

> 结论先行：**2026-09-18 那次 8 盘的样本不能作为期望值**（95% 置信区间比估计值本身还宽），
> 而"再采一点"也不解决问题 —— 需要先定精度目标，再按统计量倒推盘数；盘数直接决定预算，
> 所以**降低单盘注额是唯一能同时省钱、扩样本、压绝对波动的杠杆**。
> 本文所有数字都由 `tools/analysis/popslots/rtp_power.py` 从实测数据算出，可复现。

## 一、现有样本的统计事实

| 量 | 值 |
|---|---|
| 盘数 n | 8（spinIndex 3–10，**缺 1–2**） |
| 机器 / 注额 | `MGM` / lines=20 × bet=2500 = **每盘 50,000** |
| 总消耗 / 总派彩 | 400,000 / 110,000 |
| 实测 RTP | **27.50%** |
| 样本标准差 σ（每盘倍数） | 0.701 |

**含义**：区间宽度是估计值的 1.8 倍。这个样本既不能说明 RTP 偏低，也不能说明它正常 ——
它只能证明**采集链路可用**（这一点是确凿的）。σ 由 8 个点估出，本身也不可信，
所以下表同时给出 σ=1/2/5/8 的可能范围。

## 三、预算与 bankroll（真正的约束）

按当前 50,000/盘：

| 情形 | 盘数 | 预算 |
|---|---|---|
| ±10%（σ=2 保守） | 1,537 | 76,850,000 |
| ±5%（σ=2 保守） | 6,147 | **307,350,000** |
| ±5%（σ=8 极端） | 98,342 | 4,917,100,000 |

账号当时余额约 6,125,000 —— **连 ±5%（σ=2）的 1/50 都不够**。所以：

**把单盘降到 1/10（≈5,000/盘）后**：
- 同样预算能跑 **10× 盘数**（这正是 owner 提的方向，方法上成立）；
- 同样盘数只需 **1/10 预算**：±5%（σ=2）从 307M → **30.7M**；
- 绝对波动同比例缩小（±1σ 跑 N 盘的余额摆动 ≈ σ·√N 盘注 = 5×√6147 ≈ 392 盘注 → 由 19.6M 降到 1.96M），
  同样的余额能扛住同样多次的"打穿"。

**约束提醒**：低注额必须在**同一台机 + 同一 lines/bet 组合 + 同一版本**上做，
且该机若存在 max-bet 专属特性（部分机型有）则不能降注。

## 四、降注之前必须先做的小验证（≈200 盘 × 2 档）

RTP 与注额无关是**假设**，不是事实。先花 400 盘验证：

1. 同机同 lines，取两档注额（如 bet=250 与 bet=2500），各采 **200 盘连续**；
2. 用 `rtp_power.py` 分别算均值与 σ，比"每盘倍数"分布（均值差 / 自助法置信区间）；
3. **一致** → 可放心用低注额跑大样本；
   **不一致** → 该机有注额分层（paytable/特性随注额变），方案改为"在实际研究注额上采样"，盘数按预算上限封顶。

## 五、采集执行规则（避免把统计搞脏）

1. **连续采、不挑盘**：从某个 `sId` 起一路采到底，不做"没中奖就跳过"的筛选；
2. **记录并校验 `sId` 唯一性**（服务端 round id）→ 防重复计数/重试写入；
3. **必须包含 free spins / 奖励盘**：只算基础盘会**系统性低估** RTP。本样本 0 个 feature，
   若该机有免费旋转，说明还没采到（采到前不要下 RTP 结论）；
4. **`balanceVersion` 单调性**：断档说明漏盘（例如 8 盘样本里 spinIndex 3–10 是连续的 ✓）；
5. **分批推进**：每批 200 盘 → 重算 CI 半宽 → 半宽 ≤ 目标即停（不预设固定盘数，避免过量采样）；
6. **注额变动即分段**：换注额/换机/换版本要记 `machine + lines + bet`，分析时分组。

## 八、边界（随引用一起出现）

- 全流程**只读**：不改数值、不伪造/重放请求、不改服务器状态；动作与人类等价。
- 采集在**隔离研究实例 + 自有测试账号**上进行，次数即消耗上限，每次在 `COLLAB_LOG` 记录消耗。
- 含数值的原始数据**只留本地**（本文件与工具可入库，数据不入库）。
